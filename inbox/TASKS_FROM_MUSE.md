## 指示01（P0）セーバー枠とダイナミックプライスを区別する
現状の問題（Muse のスタブテストで実証済み）:
- host_scraper_api.py の parse_flights は「Business (I) | 93.9k」（セーバー）と「Business (JN) | 320k」（United自社便ダイナミックプライス）を全く同じ形で抽出し、運賃クラスを捨てている。そのため ANAマイルで発券できない枠が「空席あり」と表示される。

やること:
1. parse_flights の戻り値に、各クラスの運賃クラス（括弧内文字列。例: I / X / JN）を保持するフィールド（economy_fare_class / business_fare_class 等）を追加する。
2. backend/app/scraper/ua.py で、対象クラスの運賃クラスがセーバー系（ビジネス: I、エコノミー: X、ファースト: O を基本とし、提携社発券で使えるクラスとして扱う根拠を報告に書くこと）の場合のみ「ANAマイルで発券できる可能性のある空席」として扱う。ダイナミック系（JN 等）は空席判定から除外する。除外した便は件数だけでも結果に残し、「UAダイナミック枠（ANA発券対象外）N件」のように区別できる形で返す。
3. 結果データ（Redis 経由）→ フロント表示まで運賃クラスを運び、画面で対象便の運賃クラスが見えるようにする。
4. 画面に「表示マイル数は United 側の数値であり、ANA の必要マイル数とは異なる」旨の注意書きを常設する（結果エリア付近）。
受け入れ条件:
- (I) と (JN) の2種のサンプルHTMLフィクスチャで、(I) のみが空席として返り、(JN) が対象外として区別されるテストが通ること。
- 運賃クラスが取得できなかった便は「クラス不明」として空席に混ぜず、区別して扱うこと（無言で空席にしない・無言で捨てない）。

## 指示13（P1・セキュリティ）ホストAPIトークンのデフォルト値を廃止し、実値をローテーションする

### 背景（Muse の検証結果）
- 指示06で導入した共有トークンのデフォルト値 `ana-award-local-token-2026` が、公開リポジトリの `code/backend/app/config.py`、`code/host_scraper_api.py`、`.env.example` の3か所にそのままコミットされている。
- このため、実環境ファイルで別の値を設定しない限り、認証は「公開されている合言葉」で守られている状態になる。この値は公開済み＝漏洩済みとして扱い、ローテーション（新値への交換）を必須とする。Git履歴の書き換えは不要（旧値は新値への交換で無効化される）。

### やること
1. **デフォルト値の廃止**：追跡ファイルから上記の固定値を完全に除去する。
   - `config.py` のデフォルトは空文字（未設定）にする。
   - `host_scraper_api.py` 側も環境変数未設定＝空として扱う（フォールバックの固定値を置かない）。
   - `.env.example` は `HOST_API_TOKEN=` （空）＋「ランダムな値を生成して設定すること」というコメントのみにする（使える値の例は書かない）。
2. **未設定時はフェイルクローズ**：
   - ホストAPI：`HOST_API_TOKEN` が未設定/空の場合、`/api/search` と `/api/ana-autofill` は 503 を返し、ログに「HOST_API_TOKEN が未設定のため拒否」を明示する。ローカル開発で認証なしに使いたい場合のみ、環境変数 `HOST_API_ALLOW_NO_TOKEN=1` を明示したときに限り従来動作を許可し、その場合も起動ログに大きな警告を出す（デフォルトは無効）。
   - バックエンド：`host_api_token` が空かつ上記許可フラグもない場合、検索時に黙って進めず、明確なエラー（設定不足）として伝搬させる。
   - 旧値 `ana-award-local-token-2026` が設定されていた場合は「公開済みの値」として起動時に強く警告し、ローテーションを促す（可能なら拒否側に倒す。判断に迷えば報告に「要判断」で挙げること）。
3. **実値のローテーション（PC側）**：
   - ランダムな新しいトークン（32文字以上）を生成し、実環境ファイル `config/ana-award-search.env` の `HOST_API_TOKEN` に設定する。ホスト側・バックエンド側の双方が同じ実値を読む構成になっているか確認する（ホストの `load_app_env` の探索順、compose の `env_file`）。
   - **トークンの値そのものは、報告書・コミット・ログのどこにも絶対に書かないこと。** 報告には「設定済み（長さN）」「両側一致：はい」だけを書く。一致確認は値を出力しない比較スクリプトで行うこと。
4. **テストの更新・追加**：
   - `tests/test_host_api_auth.py` を新仕様に合わせて更新（固定デフォルト値前提のテストがあれば置き換える）。
   - 追加：未設定時に保護エンドポイントが 503 で拒否されるテスト／旧公開値が設定された場合に警告または拒否されるテスト／`.env.example` とコード内に旧値が残っていないことを確認するテスト（リポジトリ全体を文字列検索してよい）。
   - 既存の全テスト（33件）が引き続き通ること。
5. 作業は auto-sync ブランチで行い、完了したら `inbox/REPORT_TO_MUSE.md` に指示13として報告すること（実施内容／変更ファイル／テスト結果／未確認事項）。main への直接コミット・マージはしないこと。
